### The problem

You have an LLM-powered feature that does too much.

A single agent that researches a topic, summarizes findings, and reviews its own output is a monolith. The context window bloats. The model loses track of constraints set 3,000 tokens ago. Errors in the research phase silently corrupt the summary. You end up with a God Agent, and God Agents are a maintenance nightmare.

This is the same mistake developers made with service classes before clean architecture became standard practice. One class doing three jobs means three sets of bugs in one place, with no clean way to test any of them in isolation.

Multi-agent systems solve this the way microservices solved it for APIs: break the work into focused, independently testable units that collaborate through well-defined interfaces.
