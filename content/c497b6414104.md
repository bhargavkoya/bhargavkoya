- One server is the right place to start. Split the web tier from the data tier first, because they hit different limits.
- Add a load balancer only after the web tier is stateless. Otherwise it just routes users to the wrong machine.
- Replicas and a cache absorb reads. A CDN absorbs static files. A queue absorbs slow work.
- Sharding is the last step for the database and the hardest one to undo.
- Every step exists because something specific broke. Learn the failure first, then the fix.

### The night the estimate was off by 10x

Pokémon GO launched with a plan. Niantic set a target of 1x player traffic and estimated a worst case of about 5x.

Real traffic reached 50x the target, ten times the worst case. That is from Google’s account of the launch.

The game ran on Google Container Engine (GKE), and Cloud Datastore was its primary database. Google’s post uses Datastore traffic as a direct proxy for the game’s overall popularity, and that is the graph showing the 50x surge.
