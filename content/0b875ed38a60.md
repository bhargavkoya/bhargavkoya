## C# 14 Language Features

### The Field Keyword for Auto-Properties

C# 14 introduces the field keyword, which provides direct access to the backing field of auto-implemented properties. This feature eliminates the need for manually declaring backing fields when you need custom logic in property accessors.

```csharp
//Before C# 14:

public class Product
{
    private decimal _price;

    public decimal Price
    {
        get => _price;
        set
        {
            if (value < 0)
                throw new ArgumentException("Price cannot be negative");
            _price = value;
        }
    }
}

//With C# 14:
public class Product
{
    public decimal Price
    {
        get => field;
        set
        {
            if (value < 0)
                throw new ArgumentException("Price cannot be negative");
            field = value;
        }
    }
}
```

This feature is particularly useful for adding validation logic, logging or notifications without the ceremony of explicit backing fields. However, be cautious when using the field keyword in classes that already have a member named “field”, as the keyword takes precedence.

### Extension Members and Extension Blocks

Extension members represent a significant expansion of C#’s extension capabilities. Previously limited to extension methods, C# 14 now supports extension properties, static extension methods and even user-defined operators through the new extension keyword.

```csharp
// Extension block with instance members
extension StringExtensions(string)
{
    // Extension property
    public bool IsNullOrEmpty => string.IsNullOrEmpty(this);

    // Extension method
    public string Reverse()
    {
        char[] chars = this.ToCharArray();
        Array.Reverse(chars);
        return new string(chars);
    }
}

// Extension block with static members
extension<TSource> EnumerableExtensions(IEnumerable<TSource>)
{
    // Static extension method
    public static IEnumerable<TSource> Combine(
        IEnumerable<TSource> first,
        IEnumerable<TSource> second) => first.Concat(second);

    // Static extension property
    public static IEnumerable<TSource> Identity => Enumerable.Empty<TSource>();

    // Static user-defined operator
    public static IEnumerable<TSource> operator + (
        IEnumerable<TSource> left,
        IEnumerable<TSource> right) => left.Concat(right);
}

// Usage
string text = "hello";
bool isEmpty = text.IsNullOrEmpty; // Using extension property
string reversed = text.Reverse(); // Using extension method

var list1 = new[] { 1, 2, 3 };
var list2 = new[] { 4, 5, 6 };
var combined = list1 + list2; // Using extension operator
```

Extension blocks organize all your extensions for a type into a single, readable unit. This is especially valuable in large codebases where extensions might otherwise be scattered across multiple files.

### Null-Conditional Assignment

The null-conditional operators (?. and ?[]) now work on the left-hand side of assignments. This simplifies code that previously required explicit null checks before property assignments.

```csharp
//Before C# 14:
public void UpdateCustomer(Customer customer, Order order)
{
    if (customer != null)
    {
        customer.LastOrder = order;
    }

    if (customer?.Orders != null)
    {
        customer.Orders[0] = order;
    }
}

//With C# 14:
public void UpdateCustomer(Customer customer, Order order)
{
    customer?.LastOrder = order;
    customer?.Orders?[0] = order;
}
```

This feature reduces verbose conditional checks and makes the code more concise and readable. The right-hand side expression is only evaluated if the null check passes, maintaining the short-circuit behavior developers expect.

Important limitation: Increment and decrement operators cannot be used with null-conditional assignment.

### Partial Constructors and Partial Events

C# 14 extends partial members to include partial constructors and partial events, complementing the partial methods and properties introduced in C# 13. This is particularly useful for source generators that need to inject initialization logic.

```csharp
// Defining declaration (typically in your hand-written code)
public partial class UserService
{
    public partial UserService(ILogger logger);
    public partial event EventHandler<UserEventArgs> UserCreated;
}

// Implementing declaration (typically generated by source generators)
public partial class UserService
{
    private readonly ILogger _logger;

    public partial UserService(ILogger logger)
    {
        _logger = logger;
        _logger.LogInformation("UserService initialized");
    }

    private EventHandler<UserEventArgs>? _userCreated;

    public partial event EventHandler<UserEventArgs> UserCreated
    {
        add
        {
            _userCreated += value;
            _logger.LogDebug("Event handler added");
        }
        remove
        {
            _userCreated -= value;
            _logger.LogDebug("Event handler removed");
        }
    }
}
```

Partial constructors must include exactly one defining declaration and one implementing declaration. Only the implementing declaration can include a constructor initializer (this() or base()) and only one partial type declaration can include the primary constructor syntax.

### Lambda Parameter Modifiers Without Types

C# 14 allows lambda parameters to use ref, in, out, scoped and ref readonly modifiers without explicitly specifying parameter types. This makes high-performance lambdas more concise and readable.

```csharp
// Delegate that uses out parameter
delegate bool TryParse<T>(string text, out T result);

// C# 14: Parameter modifiers without explicit types
TryParse<int> parseInteger = (text, out result) => int.TryParse(text, out result);

// Usage
if (parseInteger("42", out int value))
{
    Console.WriteLine($"Parsed value: {value}");
}

// Example with ref parameter
delegate void Transform<T>(ref T value);
Transform<int> doubleValue = (ref value) => value *= 2;

int number = 5;
doubleValue(ref number);
Console.WriteLine(number); // Output: 10
```

This feature improves readability while maintaining type safety through inference. Note that the Action<> and Func<> delegates don't support these modifiers, so you'll need to define custom delegates. If you use the params modifier, you must still specify the parameter type.

### User-Defined Compound Assignment Operators

C# 14 enables developers to define custom implementations for compound assignment operators like +=, -=, *=, and /=. This allows fine-tuning of performance for custom types.

```csharp
public class Vector2D
{
    public double X { get; set; }
    public double Y { get; set; }

    public Vector2D(double x, double y)
    {
        X = x;
        Y = y;
    }

    // Standard operator overload
    public static Vector2D operator +(Vector2D left, Vector2D right)
    {
        return new Vector2D(left.X + right.X, left.Y + right.Y);
    }

    // Compound assignment operator overload (C# 14)
    public static Vector2D operator +=(Vector2D left, Vector2D right)
    {
        // More efficient: modify in place instead of creating new instance
        left.X += right.X;
        left.Y += right.Y;
        return left;
    }
}

// Usage
var v1 = new Vector2D(1.0, 2.0);
var v2 = new Vector2D(3.0, 4.0);

v1 += v2; // Uses optimized += operator
Console.WriteLine($"Result: ({v1.X}, {v1.Y})"); // Output: (4.0, 6.0)
```

The compound assignment operator can be optimized to modify the left operand in place, avoiding allocations and improving performance in hot paths. Without this feature, v1 += v2 would desugar to v1 = v1 + v2, creating a temporary object.

### Implicit Span Conversions

C# 14 introduces first-class support for Span<T> and ReadOnlySpan<T> with new implicit conversions. These conversions enable more natural programming with these performance-critical types.

```csharp
// Implicit conversion from array to Span<T>
int[] numbers = { 1, 2, 3, 4, 5 };
Span<int> span = numbers; // Implicit conversion in C# 14

// Implicit conversion in method calls
void ProcessData(Span<int> data)
{
    for (int i = 0; i < data.Length; i++)
    {
        data[i] *= 2;
    }
}

int[] array = { 10, 20, 30 };
ProcessData(array); // Array implicitly converts to Span<int>

// ReadOnlySpan conversions
ReadOnlySpan<char> GetTextSpan()
{
    return "Hello, World!"; // Implicit string to ReadOnlySpan<char>
}

// More natural span usage
ReadOnlySpan<byte> bytes = stackalloc byte[] { 1, 2, 3, 4 };
```

These conversions reduce the need for explicit .AsSpan() calls and make span-based APIs more accessible. This is particularly beneficial for performance-sensitive code that works with memory efficiently.

### Nameof with Unbound Generic Types

C# 14 allows the nameof operator to work with unbound generic types, simplifying reflection and diagnostic code.

```csharp
// C# 14: nameof with unbound generics
string typeName = nameof(List<>); // "List"
string fullName = nameof(Dictionary<,>); // "Dictionary"

// Useful in logging and diagnostics
public class ServiceLocator
{
    private readonly Dictionary<Type, object> _services = new();

    public void Register<T>(T instance)
    {
        var serviceType = typeof(T);
        _services[serviceType] = instance;

        // C# 14: Use nameof for cleaner logging
        Console.WriteLine($"Registered service: {nameof(T)} as {serviceType.Name}");
    }
}

// Generic constraint validation
public void ValidateType<T>() where T : class
{
    if (!typeof(T).IsClass)
    {
        throw new ArgumentException($"{nameof(T)} must be a class type");
    }
}
```

This feature is particularly useful in generic constraint validation, logging frameworks and reflection-heavy code.

## .NET 10 Runtime Performance Improvements

.NET 10 is described by Microsoft as “the fastest .NET release” to date. The performance improvements span the JIT compiler, garbage collector and runtime libraries with hundreds of optimizations compounding to deliver transformative results.

### JIT Compiler Enhancements

The Just-In-Time (JIT) compiler receives significant upgrades in .NET 10, improving code generation quality across all applications without requiring developers to change their code.

### Escape Analysis and Stack Allocation

One of the most impactful improvements is expanded escape analysis that enables stack allocation of objects. Escape analysis determines if an object can outlive its parent method. If not, the object can be allocated on the stack instead of the heap, which is much cheaper and reduces garbage collection pressure.

```csharp
// Example: Stack allocation of arrays
public static void ProcessItems()
{
    // In .NET 10, this array is stack-allocated if it doesn't escape
    string[] items = { "apple", "banana", "cherry" };

    foreach (var item in items)
    {
        Console.WriteLine(item);
    }
}

// Example: Delegate allocation elimination
public int Calculate(int value)
{
    Func<int, int> multiply = x => x * 2;
    return ApplyOperation(multiply, value);
}

private int ApplyOperation(Func<int, int> func, int arg)
{
    return func(arg);
}
```

In .NET 10, the JIT can stack-allocate:

- Small arrays of value types (no GC pointers)
- Small arrays of reference types
- Delegates that don’t escape
- Objects referenced by local struct fields

```csharp
// Small array of reference types - stack allocated in .NET 10
static void PrintMessages()
{
    string[] messages = { "Hello", "World", "from", ".NET 10" };
    foreach (var msg in messages)
    {
        Console.WriteLine(msg);
    }
}

// Local struct fields - escape analysis improvement
public class Program
{
    struct Container
    {
        public int[] Data;
    }

    public static int ProcessData()
    {
        int[] array = new int[10]; // Stack allocated in .NET 10
        Container container = new Container { Data = array };
        return container.Data[0];
    }
}
```

### Devirtualization Improvements

.NET 10 significantly improves the JIT’s ability to devirtualize method calls, particularly for array interface implementations. Arrays implement numerous interfaces (IEnumerable<T>, IList<T>, etc.), but these implementations were historically difficult for the JIT to optimize.

```csharp
// Before .NET 10: Virtual calls could not be devirtualized
public int SumWithEnumerable(int[] array)
{
    int sum = 0;
    IEnumerable<int> enumerable = array;

    foreach (var num in enumerable)
    {
        sum += num;
    }

    return sum;
}

// .NET 10: Interface calls are devirtualized
public int SumWithIndexer(ReadOnlyCollection<int> collection)
{
    int sum = 0;
    for (int i = 0; i < collection.Count; i++)
    {
        sum += collection[i]; // Now devirtualized when backed by array
    }
    return sum;
}
```

The devirtualization improvements have a cascading effect on LINQ operations, as many LINQ methods optimize for IList<T> indexing.

### Bounds Check Elimination

The JIT in .NET 10 eliminates more redundant bounds checks through improved analysis. Bounds checks ensure memory safety by preventing array access violations, but eliminating redundant checks improves performance.

```csharp
// .NET 10 eliminates redundant bounds check
public bool CompareFirstAndLast(int[] array)
{
    // First access requires bounds check
    int first = array[0];

    // In .NET 10, this doesn't need bounds check
    // If array[0] succeeded, array[^1] (array[Length-1]) is guaranteed valid
    int last = array[^1];

    return first == last;
}

// Another example: Loop with constant bounds
public int SumFirst10(int[] array)
{
    int sum = 0;

    // JIT can eliminate bounds checks after verifying array.Length >= 10
    for (int i = 0; i < 10; i++)
    {
        sum += array[i];
    }

    return sum;
}
```

### Loop Inversion and Optimization

.NET 10 enhances loop inversion by switching from lexical analysis to graph-based loop recognition. This improves precision and enables better optimization of for and while loops.

```csharp
// Loop inversion transforms this:
while (condition)
{
    // loop body
}

// Into this (conceptually):
if (condition)
{
    do
    {
        // loop body
    } while (condition);
}
```

This transformation removes the need to branch to the top of the loop for condition testing, improving code layout and enabling further optimizations like loop cloning and unrolling.

### AVX10.2 Hardware Acceleration

.NET 10 introduces support for the Advanced Vector Extensions (AVX) 10.2 instruction set for x64 processors. New intrinsics in the System.Runtime.Intrinsics.X86.Avx10v2 class enable developers to leverage cutting-edge hardware capabilities.

```csharp
using System.Runtime.Intrinsics;
using System.Runtime.Intrinsics.X86;

public class VectorOperations
{
    public static void ProcessWithAVX10()
    {
        if (Avx10v2.IsSupported)
        {
            // Use AVX10.2 optimized operations
            // Floating-point min/max operations
            // Enhanced conversion operations
            Console.WriteLine("Using AVX10.2 acceleration");
        }
        else
        {
            // Fallback implementation
            Console.WriteLine("AVX10.2 not supported");
        }
    }
}
```

AVX10.2 support is currently disabled by default because compatible hardware is not yet widely available. Once enabled, applications will automatically benefit from improved vectorization and floating-point performance.

### NativeAOT Performance

Native Ahead-of-Time (AOT) compilation in .NET 10 delivers significant improvements in startup time, memory usage and deployment size.

NativeAOT is particularly beneficial for:

- Cloud-native microservices with fast cold start requirements
- Serverless functions where startup time is critical
- Container deployments where smaller images reduce costs
- Edge devices with limited resources

## ASP.NET Core 10 Web API Features

ASP.NET Core 10 introduces improvements across routing, middleware, diagnostics and OpenAPI support.

### Enhanced Routing with Syntax Highlighting

The [Route] attribute now supports syntax highlighting to help visualize route template structure. This improves readability when working with complex routing patterns.

```csharp
[ApiController]
[Route("api/v{version:int}/[controller]")]
public class ProductsController : ControllerBase

    // Route constraints are visually distinct
    [HttpGet("search/{query:minlength(3):maxlength(100)}")]
    public IActionResult SearchProducts(string query)

        return Ok($"Searching for: {query}");
    }

```

### Middleware Pipeline Improvements

ASP.NET Core 10 refines middleware capabilities with better ordering, diagnostics and integration.

```csharp
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

// Proper middleware ordering in .NET 10
app.UseExceptionHandler("/error"); // 1. Exception handling first
app.UseHttpsRedirection();         // 2. HTTPS redirection early
app.UseRouting();                  // 3. Routing before authentication
app.UseAuthentication();           // 4. Authentication before authorization
app.UseAuthorization();            // 5. Authorization after authentication

// Custom middleware using C# 14 features
app.Use(async (context, next) =>
{
    // Null-conditional assignment (C# 14)
    context.Items["RequestId"] = Guid.NewGuid();

    await next();
});

app.MapControllers();
app.Run();
```

Best practices for middleware ordering:

- Exception handling catches all unhandled exceptions
- HTTPS redirection ensures secure communication
- Routing maps requests before authentication
- Authentication identifies users
- Authorization checks permissions
- Custom middleware for cross-cutting concerns
- Endpoints handle the actual request

## Blazor 10 UI Enhancements

Blazor 10 brings substantial improvements to reconnection handling, navigation, state persistence and JavaScript interop.

### Improved Reconnection UI

The Blazor Web App template now includes a ReconnectModal component that respects Content Security Policy (CSP) settings. This gives developers full control over the reconnection experience.

```razor
<!-- ReconnectModal.razor -->
@inject IJSRuntime JS

<div id="reconnect-modal" class="@GetModalClass()">
    <div class="reconnect-modal-content">
        @if (_state == "reconnecting")
        {
            <p>Connection lost. Attempting to reconnect...</p>
            <div class="spinner"></div>
        }
        else if (_state == "disconnected")
        {
            <p>Connection lost. Please refresh the page.</p>
            <button @onclick="RefreshPage">Refresh</button>
        }
    </div>
</div>

@code {
    private string _state = "connected";

    protected override void OnInitialized()
    {
        // Listen for reconnection state changes
        JS.InvokeVoidAsync("Blazor.addEventListener",
            "components-reconnect-state-changed",
            DotNetObjectReference.Create(this),
            nameof(OnStateChanged));
    }

    [JSInvokable]
    public void OnStateChanged(string state)
    {
        _state = state;
        StateHasChanged();
    }

    private string GetModalClass()
    {
        return _state == "connected" ? "hidden" : "visible";
    }

    private void RefreshPage()
    {
        JS.InvokeVoidAsync("location.reload");
    }
}
```

This component provides hooks like components-reconnect-state-changed and a retrying state for precise reconnection logic.

### Navigation Enhancements

NavigateTo no longer scrolls to the top for same-page navigations in .NET 10. This prevents unintentional viewport resets when updating query strings or fragments.

```razor
@page "/products"
@inject NavigationManager Navigation

<h3>Products</h3>

<div>
    <button @onclick="() => UpdateFilter("electronics")">Electronics</button>
    <button @onclick="() => UpdateFilter("clothing")">Clothing</button>
</div>

<p>Current filter: @CurrentFilter</p>

@code {
    [SupplyParameterFromQuery]
    public string? Filter { get; set; }

    private string CurrentFilter => Filter ?? "all";

    private void UpdateFilter(string category)
    {
        // In .NET 10, this doesn't scroll to the top
        Navigation.NavigateTo($"/products?filter={category}");
    }
}
```

NavLink improvements with NavLinkMatch.All now ignore query strings and fragments when determining active state, providing cleaner link highlighting.

```razor
<nav>
    <NavLink href="/products" Match="NavLinkMatch.All">
        All Products
    </NavLink>
    <NavLink href="/products?filter=electronics">
        Electronics
    </NavLink>
</nav>
```

### State Persistence in Blazor Server

.NET 10 introduces persistent component state for disconnected circuits. Components can now retain state when a circuit disconnects and restore it when the user reconnects.

```razor
@page "/task-manager"
@attribute [StreamRendering]
@inject PersistentComponentState PersistentState

<h3>Task Manager</h3>

<input @bind="NewTaskName" placeholder="Enter task name" />
<button @onclick="AddTask">Add Task</button>

<ul>
    @foreach (var task in Tasks)
    {
        <li>@task</li>
    }
</ul>

@code {
    [PersistentState] // .NET 10: Persist this property
    private List<string> Tasks { get; set; } = new();

    private string NewTaskName { get; set; } = string.Empty;

    protected override void OnInitialized()
    {
        // Automatically restored from persisted state
    }

    private void AddTask()
    {
        if (!string.IsNullOrWhiteSpace(NewTaskName))
        {
            Tasks.Add(NewTaskName);
            NewTaskName = string.Empty;
        }
    }
}
```

How state persistence works:

- When a circuit disconnects, Blazor triggers the OnPersisting event
- Properties decorated with [PersistentState] are serialized using ASP.NET Core's Data Protection APIs
- State is stored in memory or an external cache (Redis with HybridCache support)
- When the user reconnects, Blazor creates a new circuit
- Persisted state is automatically restored to the decorated properties
- Component re-renders with the restored state

Proactive circuit pausing allows developers to pause idle sessions to save resources:

```javascript
// Pause circuit after 5 minutes of inactivity
await Blazor.PauseCircuit(TimeSpan.FromMinutes(5));

// Resume when user returns
await Blazor.ResumeCircuit();
```

```razor
    }

```

### Better JavaScript Interop

Blazor 10 adds support for:

- Creating instances of JS objects using constructor functions
- Reading and modifying JS object properties (data and accessor properties)
- Improved performance for byte array transfers in WASM

